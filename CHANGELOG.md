# Changelog

Все заметные изменения в `rulemma` фиксируются в этом файле.
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), а проект следует [Semantic Versioning 2.0.0](https://semver.org/lang/ru/).

## [0.3.1] - 2026-11-27

Патч-релиз качества словарей, вывода морфологии на OOV-формах и однопроходного `lemmatize_all` с техпрофилем (100% обратная совместимость Go API, C-ABI v1 append-only, Python API и CLI).

### Исправлено

- **Системная чистка словаря `data/lemmas.tsv.gz` (`204 993 -> 214 196`, `tools/build_dicts.py`, `dict_version: 2026.11.5`):**
  - Удалены `840` OOV-обрубков, ранее попадавших в словарь как канонические или с выдуманной леммой (`кресл`, `метл -> метло`, `академи`, `алюмини` и др.): теперь `креслах -> кресло` (без обрубка `кресл`), `метл -> метл` (без выдуманного `метло`).
  - Исправлены `1 854` OOV-формы родительного падежа мужского рода на `-а`, ранее хранившиеся как отдельные леммы (`картхолдера -> картхолдер`, `ледобура -> ледобур`, `картхолдеру -> картхолдер`, `ледобуре -> ледобур` с защитой женских фамилий на `-ова/-ева/-ина`).
  - Добавлены `+10 040` отсутствовавших в ключах канонических лемм OpenCorpora (`выдача` и др.; `morph.tsv.gz`: `117 022 -> 127 163`, `alt_lemmas.tsv.gz`: `11 158 -> 11 909`), благодаря чему `fallbackSuffix` и парадигмальный морфоанализ покрывают их косвенные формы; добавлена поддержка творительного падежа `-ей` после шипящих и `ц` (`выдачей -> выдача`, `задачей -> задача`) и форм превосходной степени на `-ш-` (`высшим -> высокий`).
  - В `data/overrides.tsv` (`464 -> 470`) добавлены падежи `pluralia tantum` `тайтсы` (`тайтсы/тайтсов/тайтсам/тайтсами/тайтсах -> тайтсы`) и служебное слово `это -> это` (`analyze("это")` теперь возвращает `pos="PRCL"` вместо `ADJF` `этот`).
- **Чистка `data/adj_noun.tsv.gz` (`4 010 -> 3 960`, `tools/build_adj_noun.py`):**
  - Заблокированы `50` мусорных и нежелательных пар, включая базовые цвета (`желтый -> желтизна`, `фиолетовый -> фиогод`) и пары с выдуманным/сдвинутым существительным (`могучий -> мочь`, `худенький -> худо`, `старый -> старое`, `обрезной -> обрезок`, `плоский -> плоскость`, `коленчатый -> коленка`, `консервный -> консеров` и др.).
- **Токенизатор и ключи (`technical.go`):**
  - `CompactCodes` (`compact_codes=True`) больше не склеивает слово с числом перед единицей измерения (`"робот-пылесос roborock qrevo 5 л"` == `"робот-пылесос roborock qrevo на 5 л"` → `"5 qrevo roborock л робот-пылесос"`, при сохранении `"nike p 6000"` → `"p6000"`).
  - `KeepWords` (`keep_words`) теперь всегда имеет приоритет над стоп-словами (как дефолтными, так и кастомными): `key("класс а", stopwords={"а", "в"}, keep_words={"а"}) == "а класс"`.

### Добавлено

- **Вывод морфологии для OOV-словоформ (`morph_infer.go`, `WordInfo.Inferred`):**
  - Для словоформ, отсутствующих в `morph.tsv.gz`, `Analyze` и `PrepGoverns` теперь выводят POS, род, число и падежи без ложных догадок через: (1) точное совпадение со слотами `paradigms.tsv.gz` (`дипломом`, `академических`, `фритюрнице`, `выдачей`), (2) регулярные формы превосходной степени на `-ш-` (`высшим`), (3) известный корень-суффикс длиной `>= 5` рун у составных слов (`господдержкой` → `поддержкой`). В ответе выставляется `"inferred": true`.
- **Однопроходный `LemmatizeAllWithOptions` / `lemmatize_all(..., profile=...)`:**
  - В Go (`LemmatizeAllWithOptions`), C-ABI (append-only `rulemma_batch_all_ex`, `ABI=1`) и Python (`lemmatize_all` с `profile="technical"`, `compact_codes`, `normalize_homoglyphs`, `preserve_prep_bindings`, `bind_purpose_prep`, `keep_words`, `exclude_adj_to_noun`) добавлена поддержка опций `v0.3` в одном проходе.
- **Документация и сайт:**
  - Добавлен официальный сайт проекта [rulemma.ru](https://rulemma.ru/): бейдж и строка ссылок в шапке `README.md`, `Homepage` в метаданных пакета (`pyproject.toml`), а также ссылки `Changelog` и `Issues`.
- **CI (коммит `47a8509`):** исправлена установка `setuptools`/`wheel` в Python 3.12 и добавлена проверка платформенного wheel из `/tmp`.

### Изменения сохранённых ключей и рекомендации по переиндексации

При обновлении с `v0.3.0` на `v0.3.1` рекомендуется пересчитать сохранённые `lemma_key` / `semantic_key` для записей, содержащих:
1. Служебное слово `это` (теперь `это`, ранее `этот`).
2. Исправленные OOV-формы (`креслах -> кресло`, `картхолдеру/а -> картхолдер`, `ледобуре/а -> ледобур`, `тайтсов -> тайтсы`, `выдачей -> выдача`, `высшим -> высокий`).
3. 50 исключённых пар в `adj_noun.tsv.gz` (включая `желтый`, `фиолетовый`, `обрезной`, `плоский`, `коленчатый`).

## [0.3.0] - 2026-11-27

Минорный релиз с **3 инкрементами** (`v0.3.0-a/b/c`) при **100% обратной совместимости** дефолтных `LemmaKey`/`SemanticKey`, Go API, C-ABI v1 (строго append-only), Python API и CLI. Включает все исправления `v0.2.3`.

### Добавлено

- **Инкремент `v0.3.0-a` — Опциональный профиль технических токенов, связей предлогов и контракт `os.fork()`:**
  - **`NormalizeHomoglyphs` / `normalize_homoglyphs`:** исправляет смешанные кириллица+латиница омоглифы внутри токена (`cм -> см`, `рrо -> pro`, `intеl -> intel`, `аsus -> asus`, `оzon -> ozon`, `ryzеn -> ryzen`) без искажения чистых RU/EN токенов.
  - **`TokenizeTechnical` / `KeyWithOptions` (`profile="technical"`):**
    - сохраняет десятичные дроби (`2,6 л.с. != 6,2 л.с.`, `0,5 л == 0.5 л`, `3,3 В != 3 В`), размерности (`100×100 см != 100 см`, `500×500×500 мм`), диапазоны (`10–20`), слэш-маркеры и соотношения (`б/у`, `в/ч`, `ж/д`, `8/256`), составные единицы (`л.с.`, `кв.м`, `m.2`, `об/мин`), плюс-суффиксы (`18+`, `c++`, `pro+`, `a+++`), приклеенные единицы (`5 мм == 5мм`), границы диапазона (`до 50 см != от 50 см != 50 см`) и контекстную роль `"в"`/`"а"` после числа (`12 В` сохраняется как единица, а `3 в 1` и `ботинки 42 в москве` отбрасывают предлог `"в"`).
    - опциональные флаги: `split_hyphens` (`онлайн-курсы == онлайн курсы`), `compact_codes` (`p-6000 == p 6000 == p6000`, `мб-23 == мб 23`, `ecam 220 == ecam220`), `preserve_prep_bindings` (`«кофе без сахара с молоком»` ≠ `«кофе с сахаром без молока»`), `bind_purpose_prep` (`«пластиковые окна»` ≠ `«пластик для окон»`), `keep_words` (`«зеркальный пластик»` ≠ `«пластиковое зеркало»`) и `exclude_adj_to_noun`.
    - полная воспроизводимость старых ключей по умолчанию (`profile=None` / `"default"`).
  - **Контракт безопасности `os.fork()` в Python (`python/rulemma/_native.py`):** отслеживание PID первой загрузки `librulemma.so`; при вызове CGO в дочернем процессе после `fork()` выбрасывается понятный `RuntimeError` вместо зависания Go-рантайма, а `close()`/`__del__` безопасно пропускают вызов Go; `fork()` до создания `RuLemma()` и `multiprocessing.get_context("spawn")` работают штатно (покрыто subprocess-тестами).
- **Инкремент `v0.3.0-b` — Компактный морфоанализ известной словоформы (`morph.go`):**
  - Новые компактные словарные таблицы `data/morph.tsv.gz` (`117 022` словоформ, 32-битная битовая маска POS/род/число/падежи/одушевлённость/`Pltm`/`Sgtm`/`Fixd`, `523 КБ`) и `data/alt_lemmas.tsv.gz` (`11 158` реально омонимичных словоформ, `118 КБ`).
  - **Go/C-ABI/Python/CLI:** `Analyze(word) WordInfo` / `lem.analyze(word)`, `WordCandidates(word)` / `lem.word_candidates(word)` (`пил -> пить:VERB | пила:NOUN`, `ваз -> ваз:NOUN | ваза:NOUN`, `стали -> стать:VERB | сталь:NOUN`, `мелки -> мелок:NOUN | мелкий:ADJS`), `PrepGoverns(prep, nextWord)` / `lem.prep_governs(prep, next_word)` (`("с", "цинком") -> True`, `("к", "применению") -> True`, `("с", "1000") -> False`, `("в", "д") -> False`), CLI `rulemma analyze`.
  - Обратная совместимость `LoadFS` со старыми каталогами `data/` без `v0.3`-файлов.
- **Инкремент `v0.3.0-c` — Шаблонное склонение, согласование с числом и фонетические предлоги (`inflect.go`):**
  - Новая таблица дедуплицированных суффиксных парадигм `data/paradigms.tsv.gz` (`347` уникальных парадигм на `44 472` лемм существительных и прилагательных/причастий, `214 КБ`).

- **C-ABI (строго append-only, `ABI=1`):** `rulemma_normalize_homoglyphs`, `rulemma_tokenize_tech`, `rulemma_key_ex`, `rulemma_batch_ex`, `rulemma_analyze`, `rulemma_prep_governs`, `rulemma_inflect`, `rulemma_inflect_adj`, `rulemma_inflect_phrase`, `rulemma_all_forms`, `rulemma_agree_number`, `rulemma_preposition`.

## [0.2.3] - 2026-11-27

Патч-релиз качества морфологии, безопасности ключей и пакетного API (обратно совместимые сигнатуры Go API, C-ABI v1, Python API и CLI).

### Исправлено

- **Критичный баг безопасности и смысла в стоп-словах (`DefaultKeyStopWords` / `DEFAULT_STOP_WORDS`):**
  - Предлог отрицания **`"без"` удалён** из стандартных стоп-слов. Ранее `semantic_key("шоколад без сахара") == semantic_key("шоколад с сахаром")` и `semantic_key("котлеты без мяса") == semantic_key("котлеты с мясом")`, что склеивало противоположные по смыслу запросы.
- **Словарно-проверяемый OOV-fallback в `lemmatizer.go` (0 байт доп. RAM, `97.1%` точность на 40k OOV OpenCorpora):**
  - Убран слепой возврат неподтверждённой основы `return stem`, ранее порождавший несловарные обрубки (`пищевом -> пищев`, `трудоустройством -> трудоустройств`, `нейросетям -> нейросет`, `нервном -> нервн`, `условием -> услови`, `сухарями -> сухар`, `штангенциркулях -> штангенциркул`, `клетках -> клетк`, `колготкам -> колготк`, `втроем -> втро`, `перекрашиваем -> перекрашива`).
  - Новый fallback восстанавливает продуктивные падежные окончания существительных, прилагательных и причастий (вкл. беглые гласные `осколком -> осколок`, `противне -> противень`) **только если кандидат является подтверждённой канонической леммой** в словаре (`судебного -> судебный`, `приказа -> приказ`, `юридического -> юридический`, `замороженной -> замороженный`, `фритюрнице -> фритюрница`, `штангенциркулей/ю/е -> штангенциркуль` и др.).
- **Системное исправление ударных `-ой` прилагательных (`tools/build_dicts.py`):**
  - `беспроводной`, `складной`, `переносной`, `навесной`, `запасной`, `накладной`, `заливной`, `разливной`, `отварной` больше не деградируют в устаревшие/омонимичные `-ый` формы ни в `Word()`, ни в `AgreeAdjective()`/`BuildSEOName()` (`44` исправленных формы + переиндексация в `adj_forms.tsv.gz`).
- **`pluralia tantum`, парадигмы и дефисные города РФ (`data/overrides.tsv` `383 -> 464`, `lemmas.tsv.gz` `204 839 -> 204 993`):**
  - Исправлены: `носки -> носок` (единая парадигма с `носков/носками`), `полок -> полка`, `проводов -> провод`, `духи/духов/... -> духи`, `трусы/трусов/... -> трусы`, `сливки/сливок/... -> сливки`, `щипцы/щипцов/... -> щипцы`, `ходунки/ходунков/... -> ходунки`, `бокорезы/бокорезов/... -> бокорезы`, `сланцы/сланцев/... -> сланцы`, `румян/... -> румяна`, `берцы/берцев/берц/... -> берцы`, `лосин/... -> лосины`, `угг/уггов/... -> угги`, `джоггеры/... -> джоггер`, `шлепанцев/... -> шлепанец`, `чешек -> чешка`, `колготкам -> колготки`, `санкам -> санки`, `хлопьям -> хлопья`, `чипсам -> чипсы`, `самолигирующие -> самолигирующий`, `платят -> платить`, `сергиевом -> сергиев`.
  - Добавлены 97 падежных форм основных дефисных городов РФ (`ростов-на-дону`, `комсомольск-на-амуре`, `южно-сахалинск`, `йошкар-ола`, `санкт-петербург`, `орехово-зуево`, `петропавловск-камчатский` и др.) — несклоняемые части `-на-дону`/`-на-амуре` больше не искажаются.
- **Чистка смыслового дрейфа в `data/adj_noun.tsv.gz` (`4 030 -> 4 011`, `tools/build_adj_noun.py --in-place`):**
  - Заблокирована 21 пара смыслового дрейфа (`переносной->переноска`, `нижний->низ`, `успокоительный->успокоитель`, `взрослый->взросление`, `готовый->готовка`, `жареный->жар`, `горячий->горячее`, `советский->совет`, `местный->место`, `английский->англия`, `цифровой->цифра`, `электронный->электроника`, `компактный->компакт`, `навесной->навес`, `варочный->варка`, `военный->война`, `дополнительный->дополнение`, `профессиональный->профессионал`, `юридический->юрист`, `семеновский->семен`, `преображенский->преображение`, а также контрпример `настольный->стол` из-за коллизии «настольная игра» vs «игровой стол»).
  - Добавлены проверенные пространственные пары `напольный -> пол`, `настенный -> стена`, `петербургский -> санкт-петербург`.
- **`TypeGram` / `AgreeAdjective` / `BuildSEOName` (`data/types.tsv.gz` `4 662 -> 4 669`):**
  - Поддержано автоматическое согласование с типами во множественном числе (`купальники`, `триммеры`, `пилы`, `стиральные машины`) и многословными типами с главным словом в конце; добавлены пропущенные типы (`кофемашина femn/sing`, `мфу neut/sing` и др.) и формы `самолигирующий` в `adj_forms.tsv.gz` (`74 094 -> 74 098`).
- **Паритет токенизатора Go ↔ Python, память, wheel-теги и бенчмарк:**
  - Исправлено расхождение `NormalizePhrase("a--b")` между Go и Python (`"a b"` в обоих движках).
  - Снижен избыточный стартовый резерв Go `map` в `loadLemmasFS` (`420 000 -> 215 000`).
  - В `setup.py` добавлен платформенный `bdist_wheel` (`py3-none-linux_x86_64` / `macosx_*` вместо `py3-none-any`, когда в wheel упакована нативная `librulemma`).
  - В `benchmarks/compare_models.py` исправлен цикл генератора `build_queries` (ранее НОК `260/240` давал `3 120` уникальных строк на `20 000` входов; теперь все `20 000` запросов уникальны, в отчёте публикуются `batch_unique_queries` и `batch_unique_tokens`).

### Изменения сохранённых ключей и рекомендации по переиндексации

При обновлении с `v0.2.2` на `v0.2.3` рекомендуется пересчитать сохранённые `lemma_key` / `semantic_key` (и пересобрать зависящие от них индексы дедупликации) для записей, содержащих:
